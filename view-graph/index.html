Understand your SwiftUI app before you change it.

ViewGraph reads a SwiftUI project and draws the view graph: the screens that exist, the components they are built from, how they connect, what their previews render, and what a commit actually changes.

A comprehension tool that sits beside Xcode and your AI assistant — not a replacement for either. Everything runs locally on your Mac.

A SwiftUI app is easy to run and hard to hold in your head

The most important structure is the part nobody draws for you.

01

Structure hides in files

Views are declared one type per file, so an app's shape is spread across the whole project. Finding it means reading a lot of code that has nothing to do with your question.

02

Reuse is invisible

Nothing tells you which screens share a component. Text search finds occurrences, not relationships — and you have to remember what you already checked.

03

A diff is not a map

A pull request shows changed lines, not the screens, flows and previews those lines can break. You find out by running the app.

ViewGraph does not build, run or edit your project. It reads it, draws what it can prove, and reports what it cannot — so you spend less time reconstructing structure and more time changing it deliberately.

What it is, and what it is not

ViewGraph is early, and it is deliberately honest about that.

ViewGraph analyzes Swift source statically with swift-syntax. That means it can show structure the compiler understands, but it cannot know everything a running app does. Navigation built from data at runtime, or destinations chosen by a string, may not resolve into a connection. The canvas reports unresolved relationships rather than pretending they are complete.

Previews are rendered through Xcode and the iOS Simulator, so preview workflows need a working Xcode installation. Without it, analysis, the canvas, bookmarks and Git history still work; previews report that the toolchain is unavailable. Some project structures and preview edge cases are unsupported in the current alpha.

The production app has no telemetry and no application-managed networking. Xcode and Swift Package Manager may still download dependencies during preview workflows, and previewed project code can perform its own network requests.
